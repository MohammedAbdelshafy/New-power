## Quality Engine (Phase 3 spec — to be implemented inside Ranking + QC, not as a new system)
Per-clip scores (0–100): Hook, Retention-prediction, CTR-prediction, Visual, Audio, Subtitle, Business-value, Virality-prediction. Config: `MBM-Social/quality-thresholds.json` (created by M-008). Clips below threshold → `ClipRejected` event + requeue with reason. Scores are LLM+heuristic estimates at MVP; they become honest only after Analytics closes the loop (M-010) — the report must label them "predicted" until then.

## Sequencing (already filed as missions)
- **M-008** — MVP spine: Intake → Speech → Hook → Rank → Clip Factory. Exit: 1 long video → 3 watchable 9:16 clips, hands-off.
- **M-009** — Packaging: captions, thumbnails, publishing packages, QC thresholds. Exit: publish-ready bundle a human can post in <10 min.
- **M-010** — Validation + learning: run ≥3 approved test videos, measure runtime/CPU/RAM/failure rate/clip quality → generates the real `Production_Report.md`, `Performance_Report.md`, `Benchmark_Report.md`; analytics ledger + learning playbook.

## Bottleneck call (CTO judgment)
The pipeline's critical path is **Hook Factory quality**, not rendering plumbing — ffmpeg mechanics are commodity; picking the right 45 seconds is the product. Build M-008 around that assumption: invest LLM effort in hook selection, keep everything else minimal.
